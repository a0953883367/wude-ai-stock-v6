# AI 全能助理：五層資料與輸出驗收

## 目的

避免不同版本、研究資料與各事業資料互相混用。整理採清冊標記，不直接刪除或搬動既有正式資料。

## 五層資料

| 層級 | 用途 | 能否直接作為正式答案 |
|---|---|---|
| 正式規則（Canonical） | 已核准的規則、正式輸入與正式輸出 | 可以 |
| 長期參考（Reference） | 規格、說明及穩定背景資料 | 可作佐證 |
| 研究候選（Research） | 影子模型、試驗及待驗證方法 | 不可以 |
| 暫存資料（Temporary） | 當期報表、快取及中間產物 | 不可以 |
| 歷史封存（Archive） | 舊版及不可變更的歷史紀錄 | 只有明確稽核時載入 |

## 任務載入流程

1. 先判斷任務屬於股票、至盈、WT 或包裝創業。
2. 依任務設定選擇必要層級。
3. 先產生檔案清單，再依數量及容量上限讀取。
4. 不允許跨事業讀取；領域不明時停止。
5. 研究、暫存與封存資料不得自動改寫正式輸出。

## 文件、PPT、PDF 與報表驗收

所有輸出先標示為「草稿」，下列四項都有具體證據才可標示「可正式交付」：

1. 來源版本已核對。
2. 數字、日期及單位已核對。
3. 跨頁及跨表一致性已核對。
4. 已實際開啟或渲染，檢查截字、重疊、圖表及手機可讀性。

PPTX、DOCX、XLSX 另檢查 Office 封裝是否正常；PPTX 必須至少有一張投影片。

## 不受本次整理影響

- 正式 V6 分數、排名與權重
- 影子驗證帳本及 20／60 日累積
- 自動下單規則
- 包裝模型一、二、三
- ERP、PLC 與設備連線設定

## 現行清冊

機器可讀清冊位於 `agent_workspaces/context_catalog.json`。新增資料時先指定事業領域與五層之一；不得用未分類資料直接產出正式答案。
